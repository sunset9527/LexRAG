# 移除 LexRAG 知识图谱设计

日期：2026-10-29  
状态：实施中

## 决策

从 LexRAG 完整移除知识图谱能力。图谱没有可复现证据证明能提升当前法律检索、引用核验或回答质量，却增加了运行时分支、数据构建、依赖、测试与演示复杂度。相关内容只保留在 Git 历史中。

## 保留的核心链路

```
规划 → 知识库路由 → 法条检索（必要时案例检索）
→ 证据账本 → 回答生成 → 引用核验 → 完成
```

阶段 8 的冻结题集、BM25/向量/RRF 检索、运行时向量载荷、版本选择、证据账本、引用核验、案例检索和 SSE 问答保持不变。

法规 metadata 中的轻量“法条引用扩展”保留：它由检索优化器直接读取真实法规 metadata，不依赖 NetworkX、图数据文件或图谱 API，仍属于检索证据补充而非知识图谱。

## 删除范围

### 后端与运行时

- 删除 `src/graph/`、`src/retrieval/graph_retriever.py` 和图谱路由/模型。
- 从 API 初始化、运行时组件、健康检查、就绪探针、工作流状态与工作流节点中移除图谱。
- 删除 `/graph`、`/graph/query` 及其授权契约。
- 删除启动 bootstrap 中的图谱构建与图数据产物。
- 删除 `LAW_GRAPH_PATH` 配置、Compose 环境变量与 `networkx` 依赖。
- 从遗留 agent 工具/节点中移除图谱检索器参数和分支，避免残留导入。

### 数据库

- 从 `agent_configs` 移除 `graph_search_enabled`。
- 增加一条 Alembic 迁移，以安全的正式 schema 变更删除该列；不修改其他配置列。

### 前端

- 删除知识图谱导航、路由、页面、组件、API 类型与请求方法。
- 删除聊天工作流轨迹中的“图谱检索”显示。
- 删除管理页的图谱检索开关。

### 数据、测试与文档

- 删除阶段 8 工作区内的图谱 JSON / runtime graph 数据产物；实施前逐一列出并确认目标均位于本工作区。
- 删除图谱专属测试，更新应用工厂、健康、就绪、部署 bootstrap、路由安全、工作流和前端测试契约。
- 更新 README、部署文档、故障排查、功能台账和当前状态文档；历史归档文档不改写，以保留当时事实记录。

## 错误处理与兼容性

- `/graph` 与 `/graph/query` 不保留兼容空响应，直接删除；调用旧端点得到标准 404。
- 已存在数据库中的 `graph_search_enabled` 数据不迁移，因为该能力已删除；迁移负责丢弃该列。
- 不自动删除原始项目或工作区外路径；仅处理阶段 8 工作区内明确确认的图谱数据。

## 验收标准

1. 运行时问答不创建、加载或查询图谱，工作流轨迹中不出现 `graph_retrieval`。
2. 前端不存在知识图谱菜单、路由、页面或 API 调用；管理配置不包含图谱开关。
3. 项目依赖中不包含 NetworkX，Compose 与启动脚本不再生成或挂载图谱。
4. 数据库迁移后 `agent_configs` 不含 `graph_search_enabled`。
5. 后端相关测试、前端生产构建和图谱移除回归测试通过。
6. 阶段 8 正式检索评测可重新执行，并将结果与移除前的检索基线并列记录；不预设指标变化。
