# LexRAG v2.3 多模态法律理解设计

**日期：** 2026-10-01

**状态：** 已确认，待实施计划
**范围：** PDF 深度解析、扫描件 OCR、表格保留、合同与判决书结构化、跨文档关联、批处理及 Vue 结果预览。

## 1. 目标与边界

v2.3 将现有的 PDF/Word 异步入库能力扩展为可追溯的法律文档理解链路。系统必须让用户查看提取结果来自哪一页、哪段原文以及由何种方法得到；解析结果可用于检索和人工复核，但不构成法律意见。

本版本不抓取或宣称处理海量裁判文书，不将 OCR 或 LLM 输出视为最终法律结论，不重写已经验证的 Celery 队列、RAG 工作流或知识库隔离规则，也不接入外部云端 OCR/视觉 API。

## 2. 设计决策

采用三阶段可发布的实现，而不是一次完成全部功能：

| 阶段 | 范围 | 验收产物 |
| --- | --- | --- |
| v2.3.1 文档解析增强 | 页面级结果、OCR 来源/警告、页眉页脚降噪、原生 PDF 表格提取、详情 API/预览 | 文本型、扫描型、含表格 PDF 可独立处理，页码与来源可回溯 |
| v2.3.2 法律结构化 | 合同条款检测、判决书规则解析、受控 LLM 补充、原文回指、结构化预览 | 合同、判决书、通用文档都有确定的降级行为，正式字段均能定位来源 |
| v2.3.3 关联与批处理 | 可证据化的跨文档关联、批量投递与独立失败、关联统计预览 | 批次内文件独立完成或失败，关联边包含证据 |

现有 `DocumentJob`、`DocumentIngestionService`、`DocumentProcessingService`、`process_document_task`、自定义文档知识库及 Vue 文档中心是唯一的主链。v2.3 在其内部增加能力，不能创建第二套上传、状态或索引链路。

RapidOCR 是已有的本地扫描页回退能力，继续作为基线。PaddleOCR 仅可在同一批人工核验扫描件上完成对比后再引入，不能预先宣称准确率优势。

## 3. 架构与数据流

```text
PDF / DOCX 上传
  -> DocumentJob (UPLOADED)
  -> Celery process_document_task
  -> 页面解析：文本层 -> OCR 回退 -> 表格/页眉页脚识别
  -> 标准化页面块（文本、表格、来源、页码、置信度、警告）
  -> 文档类型识别（contract / judgment / general）
  -> 对应结构化解析器
  -> 原文、页面结果、结构化结果持久化
  -> 文本 chunks 进入既有独立 Chroma collection
  -> 可选的关联任务生成有证据的关系边
  -> READY 或 FAILED
```

`PARSING` 内部展示文本提取、OCR、表格、结构化四个子进度，不新增顶层状态。因此既有前端轮询、失败展示与 `UPLOADED -> PARSING -> CHUNKING -> INDEXING -> READY/FAILED` 状态契约继续成立。

解析优先使用确定性规则。LLM 只可用于规则未覆盖的结构化补充，并且每个被持久化的字段必须回指输入原文；无法回指的输出丢弃或标为未识别。

## 4. 数据模型

保留 `document_jobs` 原字段和现有序列化契约。新增模型：

| 模型 | 责任 | 主要字段 |
| --- | --- | --- |
| `document_pages` | 保存逐页、可复核的解析结果 | `id`, `document_id`, `page_number`, `text`, `source`, `ocr_confidence`, `header`, `footer`, `parse_warnings` |
| `document_structures` | 保存单个文档的结构化结果 | `document_id`, `document_type`, `content_json`, `parser_version`, `status`, `error_message` |
| `document_relations` | 保存可解释的跨文档关联边 | `id`, `source_document_id`, `source_locator`, `target_type`, `target_id`, `relation_type`, `law_article`, `similarity`, `evidence_text`, `created_by`, `engine_version` |

结构化 JSON 的每个字段都包含 `value`、`page_number`、`evidence_text`、`extraction_method` 和可选 `confidence`。`confidence` 表示提取系统的信号，不表示法律真实性。

数据库迁移必须先创建新表和索引；不得破坏既有 `document_jobs` 数据。文档与关系查询必须校验其所属文档库；当前文档 API 尚未接入 JWT 用户鉴权，v2.3 不暗中扩展权限系统，用户级隔离留待 v3.0 RBAC。

## 5. 解析规则

### PDF 与 OCR

- 文本层存在且满足阈值时直接使用，不调用 OCR。
- 扫描页调用本地 RapidOCR；保存页码、来源和可用置信度。单页 OCR 失败记录警告并继续其他页面。
- 所有页面均无可索引文本时，任务失败；部分页面失败时，任务可继续完成。
- 页眉页脚通过跨页重复、位置和短文本规则识别，原始结果保留但默认不进入检索正文，防止页码、案号等污染召回。

### 表格

- 原生 PDF 的矢量表格提取为行列结构，并保存页码、边界和提取方式。
- 扫描表格仅保存 OCR 后的表格候选文本及低可信提示；不得把行序硬转换为可靠单元格。
- DOCX 延续已有段落和表格行提取行为，并给表格内容添加结构化来源标记。

### 合同

- 先识别 `第一条`、`第 X 条`、`1.1` 等条款编号，保存条款的页码、标题、原文范围。
- 规则分类：当事人、标的、价款、履行、违约、免责、争议解决、管辖、期限。
- 关键字段只能从匹配条款的原文中提取；不确定时输出“未识别”。

### 判决书

- 根据常见标题及段落锚点提取当事人、案由、诉讼请求、查明事实、法院认为、裁判结果、引用法条。
- 每一字段都绑定页码和原文片段。非标准格式可调用一次受控 LLM 补充，但没有原文支持的字段不得进入正式结果。

### 跨文档关联

仅允许三种边：明确法条编号一致、同一知识库内语义相似、合同条款与已检索法规证据匹配。每条边必须记录原文证据、法条号或相似度、建立方法和引擎版本。相似度边是“相关候选”，不是法律适用结论；不同知识库的证据不得合并为同一来源。

## 6. API 契约

既有上传、任务列表、单任务查询、失败重试接口维持不变。新增：

| 接口 | 用途 | 关键限制 |
| --- | --- | --- |
| `GET /documents/{id}/result` | 文档概要、结构化字段、表格统计与来源 | 不返回存储绝对路径、提示词或密钥 |
| `GET /documents/{id}/pages` | 分页读取逐页解析结果 | 校验文档与文档库归属；用户级鉴权待 v3.0 RBAC |
| `GET /documents/{id}/relations` | 读取该文档的已证据化关联 | 关联需包含证据或相似度说明 |
| `POST /document-libraries/{slug}/documents/batch` | 将多文件逐一建立异步任务 | 单个文件失败不得回滚整批 |

批量接口先校验每一上传文件并创建独立 `DocumentJob`，随后分别投递现有 Celery worker。响应包含每个文件的任务 ID 或独立校验错误。

## 7. 前端设计

保留“文档解析中心”为入口，新增多文件选择与逐文件状态。任务详情采用抽屉或独立页面，展示页面文本、OCR 来源、解析警告、表格预览、合同/判决书字段，以及关联法条/案例候选。

每个结构化字段显示页码与原文依据。OCR 结果、低置信度字段和语义相似关联均使用明确提示。前端只展示处理状态、结果和证据，不展示模型思维链、原始存储路径、提示词或密钥。

## 8. 容错与安全

- OCR、表格抽取、结构化解析均可降级，纯文本入库主链不能因任一可选步骤失败而中断。
- 文档类型不确定时按 `general` 处理，仍可检索，不强套合同或判决书结构。
- LLM 不可用时只执行规则解析，明确标注方法，文档仍可进入索引。
- 批量任务独立失败；失败信息、时间、重试入口可见。
- 不返回原始文件存储路径；所有新接口校验文档与知识库归属。当前文档 API 无用户级鉴权，v2.3 不将其误述为已实现。

## 9. 验收与测试策略

严格测试先行：每一生产行为先新增会失败的测试，确认失败原因后再做最小实现。

| 层次 | 覆盖内容 |
| --- | --- |
| 单元测试 | 页面来源、OCR 回退、页眉页脚、表格、条款/判决书解析、关系去重及证据回指 |
| 服务与 API 契约 | 状态推进、分页、批量部分失败、权限隔离、存储路径不泄漏 |
| 前端 | 批量上传、轮询、状态与低置信度提示、详情渲染、生产构建 |
| 真实人工复核 | 固定可追溯小样本上的 OCR 字符错误、字段可回指率、表格可用率、关联人工确认率 |

人工样本不足时，对应指标必须为空并说明原因。规则命中数、模型自评或未标注样本不得表述为法律准确率。

## 10. 非目标与后续决策

新 OCR 引擎、外部视觉服务、文书网采集及大规模案例统计属于后续独立设计。v2.3 完成后，才根据真实人工复核数据决定是否优化 OCR、增加解析规则或扩大批处理规模。
