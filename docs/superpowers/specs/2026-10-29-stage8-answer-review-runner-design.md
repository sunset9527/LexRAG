# Stage 8 真实回答审核运行器设计

日期：2026-10-29  
状态：运行器已实现，等待真实认证运行

## 目标

对冻结的 100 条 Stage 8 回答审核样本运行真实 `/query` 工作流，生成供人工审核的逐题记录。运行器只读取当前 PowerShell 进程的 `STAGE8_LLM_API_KEY` 与 `STAGE8_AUTH_TOKEN`，绝不将凭据写入文件、日志、数据库、报告或命令行参数。

## 输入与边界

- 固定输入为 `data/evaluation/stage8/stage8_answer_review_sample_100.jsonl` 及其 manifest。
- 冻结 280 条题集只读；运行器不得更改题干、标签、审核状态或来源字段。
- Key 或登录令牌缺失时在任何请求前失败；请求认证失败、超时或工作流异常逐题记录脱敏错误类型，不从分母静默删除。
- 运行器使用本机 API 的 BYOK 请求头；不读取浏览器内存、Cookie 或 Settings 存储。

## 输出

输出到新的、带运行时间戳的 Stage 8 answer-run JSONL 与 manifest。每行包含：题目 ID、问题、选择的知识库、回答、引用、工作流轨迹、延迟、验证状态、降级原因或脱敏错误类型。manifest 绑定样本与结果 SHA-256、运行配置、依赖版本及成功/失败计数。

## 执行策略

- 顺序执行，避免 100 条并发消耗不可控额度并保持可复核顺序。
- 对每条请求应用明确超时；网络/服务错误最多一次受控重试。
- 运行完成后仅汇总执行结果，不计算 Ragas、Judge 或法律正确率；这些由后续人工审核和独立诊断步骤消费相同逐题输出。

## 验收

1. 无 Key 时不发送请求且失败信息不包含密钥。
2. 成功/失败记录均可由题目 ID 对应到冻结样本。
3. 输出不包含 API Key 或 Authorization/X-API-Key 原文。
4. 100 条样本全部产生一条可审核结果或显式执行错误。
5. 结果文件和 manifest 可由测试验证其字段、计数和哈希绑定。
