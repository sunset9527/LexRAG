# Stage 4：法规版本链与核验门槛

## 目标

将用户下载的法规原件保持为可追溯候选来源，并只让已核验、在指定日期有效的完整版本进入隔离索引。现有知识库指针保持不变，直到新索引通过验证后才允许切换。

## 范围

- 候选法规有独立的权威核验状态、官方 URL 与核验时间。
- 同一法律可由基准全文和按日期排序的修正案组成版本链。
- 刑法链固定表达为：2020 基准全文（已含修正案十一）加修正案十二；修正案十、十一保留为历史溯源，不重复应用。
- 当前适用版本必须有经人工核验的完整合并文本；系统不自动改写条文，也不将修正案片段当作全文索引。
- 索引前校验候选来源、版本链和生效时间；不满足时拒绝创建或切换索引。
- 引用与检索元数据必须携带 `version_id`、`effective_from`、`effective_to`、`source_url`、`content_hash`。

## 数据与状态

候选来源继续存于 `legal_source_imports`，默认 `PENDING_REVIEW`。核验后可标记为 `VERIFIED` 并写入官方 URL。版本链记录基准全文、修正案来源、目标版本、生效区间和状态。

`PENDING_REVIEW`、缺失官方 URL、只有修正案但无完整文本、或尚未生效的版本均不可索引。失败不会覆盖现有 Chroma collection。

## 流程

管理员核验来源并建立版本链 → 提供或审核完整合并文本 → 校验哈希、条文结构和适用日期 → 建立隔离 collection → 读回校验 → 原子切换知识库指针。旧 collection 保留以便回滚。

## 接口与测试

管理员可查看候选来源与版本链，但正文不在列表接口返回。服务层提供：核验来源、创建版本链、按日期获得可索引版本。测试覆盖：刑法链不重复应用修正案、未核验或未生效链被拒绝、元数据完整、切换失败保持旧指针。

## 非目标

不自动从网页抓取法规；不自动把修正案文本补写进基准全文；不把宪法、治安管理处罚法和 EPUB/PDF 扩展进本轮八部法范围。
