# LexRAG v2.0：检索增强与质量兜底设计

**状态**：待用户审阅  
**日期**：2026-09-30

## 目标与边界

v2.0 在既有法规、案例与自定义文档三类独立知识库之上，补齐检索质量、查询性能与用户留存能力：HyDE、多候选查询改写、Redis 缓存、收藏、可复现检索评测和模型配置校验。

本版本不实施司法解释库、法条版本链、多 Agent 或合同审查；它们属于 v1.9 遗留和后续版本。PDF/Word 文档解析中心已经完成代码、自动化验证和 DOCX 端到端验收，但尚未完成本机全服务启动后的人工 PDF/Word 部署验收，也不属于 v2.0 新功能。

所有新指标只由带有真实法条标注的评测样本计算。不得补造样本、正确法条或提升结果。

## 方案选择

采用分阶段、可回归的实现方式：先建立评测数据契约和运行器，再接入检索增强，之后实现缓存与收藏，最后补齐前端和端到端验证。

相比“先加功能后补评测”，该顺序能证明 HyDE/改写是否产生真实增益；相比一次性重写工作流，能在每一阶段保留既有问答降级路径。

## 架构与数据流

### 1. 可复现评测

- 新增版本化 JSONL 评测集，每行包含 `id`、`query`、`knowledge_base_slug`、人工核验的 `relevant_article_ids`、`source` 与 `reviewed_at`。
- 新增离线运行器，分别输出 Recall@K、MRR 与 NDCG@K，并保存每条 query 的候选条文和排名，供人工复核。
- 现有 15 条民法典评测可迁入为初始基线；扩充样本前必须逐条人工核验。未达到 50 条时，报告真实样本数，不将其表述为“50 条评测”。

### 2. 多路检索增强

- `QueryRewriter` 将生成最多 3 个去重的法律检索候选；解析失败、超时或候选为空时回退原问题。
- HyDE 将为原问题生成一段仅用于向量召回的假设文本；它不会作为法条事实、答案或引用展示给用户。
- 检索服务对原问题、改写候选和 HyDE 各自召回，在同一 `READY` 知识库范围内使用 RRF 融合、去重并保留来源查询信息。法规、案例和文档 collection 继续隔离，不跨库混检。
- 任一 LLM 增强步骤失败时，执行现有原问题检索；向调用方返回降级标记，但不使问答失败。

### 3. Redis 缓存

- 精确缓存 TTL 为 1 小时，缓存的是已完成的检索/问答结果及其引用，不缓存异常或降级失败结果。
- 缓存键包含用户、规范化问题、知识库、Base URL、模型、Prompt 版本及检索配置版本，避免跨用户或跨配置复用回答。
- 语义近似命中使用本地 BGE-M3 向量，在同一缓存作用域内以余弦相似度大于 0.9 判断。响应 metadata 标注 `cache_hit=semantic`、命中的原始问题和相似度；前端明确提示“基于相似问题的缓存结果”。
- Redis 不可用时，记录可观察日志并绕过缓存，正常执行检索和问答。

### 4. 收藏

- 新增 `favorites` 表：`id`、`user_id`、`question`、`answer`、`citations_json`、`knowledge_base_slug`、`law_area`、`created_at`；对同一用户的等价收藏建立唯一约束。
- API 提供创建、列表（支持领域与知识库过滤）和删除；只能访问当前用户的收藏。
- 法律咨询结果页提供收藏/取消收藏；收藏页显示原问题、回答摘要、引用数量、领域和创建时间，可跳回完整内容。

### 5. 模型配置校验

- 保留现有浏览器 localStorage + 请求头注入机制，不存储用户 API Key。
- 前端提供商列表作为受支持配置的提示；后端验证 Base URL、模型名和必需请求头的基本格式。
- 无 API Key 时，法规浏览、案例库、文档中心和离线评测保持可用；需要 LLM 的改写、HyDE 与答案生成走原有清晰错误/降级路径。

## 错误处理与可观测性

- 为每次查询记录增强是否启用、回退原因、每路候选数、缓存命中类型与耗时；不得记录 API Key 或完整敏感用户输入到公开日志。
- 评测运行器对缺失知识库、无效标注或无法检索的样本报出逐条错误，并以非零退出码结束。
- 收藏、缓存与评测不改变已有自校验及引用溯源语义。

## 测试策略与完成标准

1. 先为 JSONL 标注校验、指标计算、候选改写去重/回退、HyDE 失败回退和 RRF 来源融合编写离线失败测试。
2. 再为缓存键隔离、精确/语义命中、Redis 失效旁路、收藏授权与去重编写 API/服务层失败测试。
3. 使用真实人工标注样本运行评测；报告样本数和实际数值，不预设或修改预期指标。
4. 运行后端相关测试、全量回归测试及 Vue 生产构建。只有测试通过且输出无异常时才更新 README/路线图中的完成声明。

## 分阶段交付

1. 评测数据契约与指标运行器。
2. 多候选改写与 HyDE 检索融合。
3. Redis 缓存与前端缓存状态提示。
4. 收藏后端、前端和授权校验。
5. 全量验证、真实评测记录与文档同步。
